cd <directory>
说明：进入指定文件夹。

mkdir <directory>
说明：在当前工作文件夹下创建文件夹。

pwd
说明：显示当前工作文件夹的完整路径。

git -v
说明：显示本机的 Git 版本号。

git init
说明：把当前工作文件夹初始化为 Git 仓库。

git add <file>
说明：把工作区中指定文件的当前内容加入暂存区，暂存区可以保存多个文件，后续运行 git commit 会把暂存区里的修改一起保存为一个 commit。
注释1：暂存区保存的是最后一次对该文件执行 git add 时的内容，不会随文件的修改和保存自动更新。如果之后又修改了文件，需要再次执行 git add，才能将新的修改加入暂存区。
注释2：git commit 提交的是暂存区中的内容。
注释3：对于未跟踪的新文件，git add 会将其纳入跟踪并加入暂存区。没有执行 git add 的新文件，不会因执行普通的 git commit 自动进入提交。
注释4：已经被跟踪的文件，后续修改时即使没有执行 git add，也仍然被跟踪，只是新的修改尚未进入暂存区。

git add -A
说明：把整个仓库中所有文件的修改、新增和删除加入暂存区。
注释：被 .gitignore 忽略的未跟踪文件不会加入暂存区；已经被 Git 跟踪的文件不受这条忽略规则影响。

git commit -m "<message>"
说明：把暂存区中的内容保存为一个新的提交，<message> 是这次提交的说明。
注释1：每个提交保存该版本所有受 Git 跟踪文件的快照，不只是本次修改的文件。
注释2：提交后暂存区不会清空，而是与刚生成的提交内容一致，因此不再有待提交的差异。
注释3：提交不会自动把工作区中尚未暂存的修改加入提交。

git status
说明：查看仓库的状态，比如哪些文件有已暂存的修改、哪些文件修改了但尚未暂存、哪些新增文件尚未被跟踪。
注释1：Changes to be committed 表示暂存区与最近一次提交之间存在差异，这些修改将进入下一次提交。
注释2：Changes not staged for commit 表示工作区与暂存区之间存在差异，这些修改尚未暂存。
注释3：Untracked files 表示尚未被 Git 跟踪的文件。
注释4：同一个文件可以同时有已暂存和未暂存的修改。

git diff <file>
说明：查看指定文件在工作区与暂存区之间的差异。
注释：通常不显示未跟踪文件的内容。

git diff --cached <file>
说明：查看指定文件在暂存区与最近一次提交之间的差异。

git diff HEAD <file>
说明：查看指定文件在工作区与最近一次提交之间的差异。

git log
说明：查看当前提交及其祖先提交的历史记录，包括提交 ID、作者、时间和提交说明等。
注释：例如 commit f10d48bfd5d5e88ffabdc5a944f14dcc7b3193da，其中后面的字符串就是该提交的编号，即 commit ID。

git log --pretty=oneline
说明：用一行显示一条提交记录，包含完整的提交 ID 和提交说明。

git reset
说明：可用于移动当前分支的位置，以及重置暂存区；是否更新工作区取决于所选模式。
注释1：HEAD 通常指向当前分支，并通过分支指向当前提交。
注释2：HEAD^ 表示当前提交的第一个父提交，HEAD^^ 表示沿这条父提交路线再往前一个提交，HEAD~100 表示沿第一父提交路线向前追溯 100 个提交。
注释3：--hard 会把当前分支移到指定提交，并用该提交的文件快照恢复暂存区和工作区中受 Git 跟踪的文件。
注释4：--soft 会把当前分支移到指定提交，暂存区和工作区保持不变。
注释5：--mixed 会把当前分支移到指定提交，并用该提交的文件快照恢复暂存区，工作区保持不变；这是默认模式。
注释6：直接执行 git reset，相当于 git reset --mixed HEAD，会取消所有已暂存的修改，工作区保持不变。

git reset --hard HEAD^
说明：回退到当前提交的第一个父提交，并将暂存区和工作区恢复为该提交的内容。
注释：会丢弃受影响文件尚未提交的修改，执行前应确认这些修改不再需要。

git reset --hard <commit_id>
说明：把当前分支移到指定提交，并将暂存区和工作区恢复为该提交的内容。既可以回退，也可以在回退后使用原来的提交 ID 恢复。
注释1：恢复的是该提交中保存的文件快照，并不是当时未提交的工作区或暂存区状态。
注释2：目标提交中没有、但当前已被 Git 跟踪的文件，可能会在恢复过程中被删除。
注释3：未跟踪文件通常会保留，但如果它们妨碍恢复目标提交中的文件，也可能被覆盖或删除。

git reflog
说明：查看 HEAD 的移动记录，可以通过记录中的提交 ID 找到回退前的位置，再使用 git reset 恢复。
注释1：例如：23d9421 (HEAD -> master) HEAD@{0}: reset: moving to 23d9421
注释2：23d9421 表示该次操作完成后 HEAD 指向的提交 ID。
注释3：(HEAD -> master) 表示当前 HEAD 指向 master 分支，而 master 当前指向这一行对应的提交。它显示的是现在的位置，不一定是操作发生时的分支状态。
注释4：HEAD@{n} 表示 HEAD 最近第 n+1 条移动记录，HEAD@{0} 是最新一条。
注释5：reset: moving to 23d9421 表示这次记录对应一次 reset 操作，目标是 23d9421，并不是完整的原始命令。
注释6：reflog 主要帮助找回提交，不能保证找回未提交的修改，记录也不会永久保留。

git checkout -- <file>
说明：用暂存区中的文件内容覆盖工作区中的指定文件，暂存区保持不变。
注释1：git commit 不会清空暂存区，因此提交后修改文件，再执行此命令，仍然是拿暂存区的内容覆盖工作区。
注释2：该文件尚未暂存的修改会被丢弃。
注释3：-- 用于明确后面是文件路径，避免与分支名等产生歧义；不加 -- 不一定就是切换分支，Git 会根据参数进行判断。

git checkout <commit_id> <file>
说明：从指定提交中取出文件，同时更新暂存区和工作区中的该文件，当前分支的位置保持不变。
注释：可以在提交 ID 和文件路径之间加上 --，明确区分版本与文件路径。

git reset HEAD <file>
说明：把暂存区中的指定文件恢复为 HEAD 中的内容，不修改工作区，也不移动 HEAD 或当前分支。
注释1：适用于已经执行 git add，但想取消暂存的情况。
注释2：如果 HEAD 中没有该文件，执行后会从暂存区移除它，工作区文件保留并变为未跟踪文件。
注释3：如果随后执行 git checkout -- <file>，且 HEAD 中存在该文件，工作区中的该文件也会恢复为 HEAD 中的内容。

git rm <file>
说明：删除工作区和暂存区中的指定文件，将这次删除加入下一次提交。
注释1：适用于已经被 Git 跟踪的文件，未跟踪文件可以直接使用 rm 删除。
注释2：执行后需要运行 git commit，才能把删除记录到新的提交中。
注释3：不会修改之前已有的提交，旧提交中仍然保留该文件，可以从历史提交中恢复。比如工作区误删某个文件，可以通过git checkout -- <file>的操作恢复到最近一次的暂存区该文件。
注释4：如果文件有尚未保存到提交的修改，Git 可能会拒绝删除，以避免丢失内容。

git rm --cached <file>
说明：只从暂存区移除指定文件，保留工作区中的文件，用于停止跟踪该文件。
注释1：如果最近一次提交中包含该文件，执行后会暂存一次删除，需要运行 git commit 才能将这次变化记录到新提交中。
注释2：工作区中的文件会成为未跟踪文件；如果匹配 .gitignore 规则，则会被忽略。
注释3：不会修改之前已有的提交，旧提交中仍然保留该文件。
注释4：如果希望之后执行 git add -A 时不再加入该文件，还需要将其加入 .gitignore。
